# simplang 言語仕様

simplang は Rust に似た構文の小さな言語で、静的に型付けされ、x86-64 ネイティブバイナリへコンパイルされる。
本書は**現時点の**言語仕様をまとめたもので、機能を追加・変更したら必ず更新する。
各機能を導入した経緯・検討した代替案は `docs/stepNNN.md` を参照（目次は `docs/README.md`）。

```
// util.sl
fn sq(x: i64) -> i64 { x * x }

// main.sl
import "util.sl";

fn sum(p: &[i64; 5]) -> i64 {
    let total = 0;
    let i = 0usize;
    while i < 5 {
        total = total + p[i];
        i = i + 1;
    }
    total
}

fn main() -> i64 {
    let a = [3, 1, 4, 1, 5];
    sum(&a) + sq(2)
}
```

（上記の `//` は説明用。simplang のソースにコメントは書けない）

## 1. プログラムの構成

```
program     ::= import-decl* item*
import-decl ::= 'import' STRING ';'
item        ::= fn-decl | const-decl | static-decl
fn-decl     ::= 'fn' IDENT '(' (IDENT ':' type (',' IDENT ':' type)*)? ')' ('->' type)? '{' stmt* expr? '}'
const-decl  ::= 'const' IDENT ':' type '=' expr ';'
static-decl ::= 'static' IDENT ':' type '=' expr ';'
```

- トップレベルには `import`、`fn` 定義、`const`/`static` の定義だけを書ける（文・式は書けない）。`import` は他の定義より前に書く
- `fn main()` がプログラムの入口。リンクする全ソースを通してちょうど1つ必要（→ 5.3）
- fn・const・static の宣言順に意味は無い（後で定義した fn も、相互再帰も呼べる。後で定義した const も参照できる）
- コメント構文は無い

## 2. 字句

| 種類 | 内容 |
|---|---|
| キーワード | `fn` `let` `if` `else` `while` `break` `continue` `return` `true` `false` `as` `import` `const` `static` |
| 識別子 | 英字で始まり、英数字と `_` が続く |
| 整数リテラル | 10進のみ。`42`（型なし）、`42i32` `42i64` `42u32` `42u64` `42usize`（型サフィックス付き。空白を挟まない） |
| 文字列リテラル | `"..."`。import のパス指定にのみ使う。エスケープは無く、改行を含められない |
| 記号 | `+ - * / ! & = == != < <= > >= -> ( ) { } [ ] , : ;` |

## 3. 型

| 型 | 内容 | 格納サイズ |
|---|---|---|
| `i32` / `i64` | 符号あり整数 | 4 / 8 バイト |
| `u32` / `u64` | 符号なし整数 | 4 / 8 バイト |
| `usize` | 配列の添字用の符号なし整数。表現は u64 と同じだが、**u64 とは別の型** | 8 バイト |
| `bool` | `true` / `false` | 4 バイト |
| `()` | ユニット型。値は `()` のみ | 4 バイト |
| `&T` | `T` へのポインタ。`&&i64` のように任意段数ネストできる | 8 バイト |
| `[T; N]` | 要素型 `T`、要素数 `N`（1以上の整数リテラル）の配列 | N × T の格納サイズ |

- **暗黙の型変換は一切行わない**。整数型どうしでも符号・幅が違えば型エラーで、変換は `as` で明示する（→ 4.4）
- 配列の要素型はスカラー型（整数・bool・()）とポインタ型（配列へのポインタを含む）。配列の中に配列は置けない
- 配列はローカル変数と static としてのみ存在できる（→ 6、7）

## 4. 式

### 4.1 演算子の優先順位

上ほど弱く結合する。二項演算子はすべて左結合。

| 優先順位 | 演算子 | 被演算子 | 結果 |
|---|---|---|---|
| 1（最弱） | `==` `!=` | 同じ型どうし（整数・bool・()・ポインタ） | bool |
| 2 | `<` `<=` `>` `>=` | 同じ型どうし（整数・ポインタ。bool と () は不可） | bool |
| 3 | `+` `-` | 同じ整数型どうし | 同じ整数型 |
| 4 | `*` `/` | 同じ整数型どうし | 同じ整数型 |
| 5 | `as` 型（後置） | 整数型 | キャスト先の整数型 |
| 6 | `-` `!` `&` `*`（前置の単項演算子） | → 4.3 | |
| 7（最強） | `a[i]`（後置の添字） | 配列 / 配列へのポインタ | 要素型 |

- `-x as i32` は `(-x) as i32`、`-a[0]` は `-(a[0])`、`&a[i]` は `&(a[i])`
- `a < b < c` は `(a < b) < c` と解釈され、bool どうしの大小比較として型エラーになる

### 4.2 整数演算

- 演算結果は型の幅でラップアラウンドする（オーバーフローは検出しない）
- 除算は 0 方向への切り捨て。`最小値 / -1` は例外にならず最小値へラップする
- 0 による除算は実行時エラー（`division by zero` を出力して終了コード 1）
- 符号なし整数に単項マイナスは使えない（`0u32 - x` のように書く）

### 4.3 単項演算子

| 演算子 | 意味 | 被演算子 |
|---|---|---|
| `-e` | 符号反転 | 符号あり整数 |
| `!e` | 論理否定 | bool |
| `&e` | アドレス取得。結果は `&T` | 場所式（変数、`*p`、`a[i]`）のみ |
| `*e` | 参照外し。`&T` から `T` を読む | ポインタ |

### 4.4 キャスト `e as T`

- キャスト先 `T` は整数型（`i32` `i64` `u32` `u64` `usize`）のみ。被演算子も整数型のみ（bool・ポインタからは不可）
- Rust の `as` と同じくビットを再解釈する。縮小は下位ビットの切り詰め、拡大はキャスト元の符号に従って符号拡張／ゼロ拡張
- `x as i64 as i32` のように連鎖できる

### 4.5 整数リテラルの型

- 型サフィックス付き（`5i32` `5usize` など）は常にその型
- 型なし（`5`）は文脈が期待する整数型になる。`let x = 5;` のように文脈から決まらなければ `i64`
- 範囲外の値はその型の幅でラップする

### 4.6 その他の式

- 関数呼び出し `f(a, b)`：実引数は仮引数の型と厳密に一致しなければならない
- 配列リテラル `[e1, e2, ...]` / `[e; N]`：`let` の初期化式でのみ使える（→ 6）
- `()`：ユニット値
- `(e)`：括弧

## 5. 文と関数

### 5.1 文

| 文 | 内容 |
|---|---|
| `let x: T = e;` | 変数宣言。型注釈を省略すると `e` の型になる（文脈が無い整数リテラルだけなら i64） |
| `x = e;` | 代入。`e` は `x` の型と一致しなければならない |
| `a[i] = e;` / `p[i] = e;` / `(*p)[i] = e;` / `*p = e;` | 場所式への代入 |
| `e;` | 式文。値を捨てる（型は問わない） |
| `{ ... }` | ブロック（→ 5.2） |
| `if c { ... } else if c2 { ... } else { ... }` | 条件分岐。条件は bool。値は返さない |
| `while c { ... }` | ループ。条件は bool |
| `break;` / `continue;` | 直近の外側のループを抜ける／条件の判定へ戻る。ループ外では使えない |
| `return e;` / `return;` | 関数から戻る。`return;` は `return ();` と同じ |

- 変数は宣言時に必ず初期化する。すべての変数は再代入できる（`mut` は無い）
- `if` / `while` / ブロックは文であり、値を返さない

### 5.2 スコープ

- `{}` ブロック、`if` の各分岐、`while` の本体はそれぞれ新しいスコープを作る。内側で宣言した変数は外へ出ると見えない
- 外側と同名の変数を内側で宣言できる（シャドーイング）。同じスコープでの再宣言はエラー
- 関数本体は仮引数だけを含むスコープから始まる。他の関数の変数は見えない。その外側に const/static のスコープがある（→ 7）
- let・仮引数で const/static と同名の変数は宣言できない

### 5.3 関数

- 仮引数の型注釈は必須。`->` を省略した戻り値型は `()`（推論はしない）
- 仮引数は最大 6 個
- 本体の末尾式が戻り値になる。末尾式を省略すると `()` を返す
- 仮引数・戻り値に配列型 `[T; N]` は使えない。`&[T; N]` で受け渡す
- ローカル変数を指すポインタ（`&x`、`&a[i]`）を直接 `return` / 末尾式にするとエラー（ダングリングポインタの簡易検出。中間変数を経由した場合は検出しない）

### 5.4 main

- `fn main()` は引数を取れず、他の関数から呼び出せない
- 戻り値は終了時に標準出力へ表示される

| main の戻り値型 | 出力（末尾に改行） |
|---|---|
| `i32` / `i64` | 10進数（符号あり） |
| `u32` / `u64` / `usize` | 10進数（符号なし） |
| `bool` | `true` / `false` |
| `&T` | アドレス（printf の `%p`） |
| `()` | 何も出力しない |

- プロセスの終了コードは正常終了なら 0、実行時エラー（ゼロ除算・添字の範囲外）なら 1

## 6. 配列

```
let a: [i64; 3] = [1, 2, 3];
let b = [0u32; 10];          // [e; N]: e を1回だけ評価して N 個並べる
a[0] = a[1] + a[2];
let p: &[i64; 3] = &a;
p[2] = 9;                    // 配列へのポインタは添字で自動的に参照外しされる（(*p)[2] と同じ）
```

- 添字は `usize` 型。型なし整数リテラルは usize として扱われる
- 範囲外の添字は実行時エラー（`index out of bounds` を出力して終了コード 1）。リテラルの添字はコンパイル時にも検査する
- 配列リテラルの要素数は宣言した型の `N` と一致しなければならない。空の配列リテラル `[]` は書けない
- 配列を値として使うことはできない：配列全体の代入、`let b = a;`、`*p`（p: `&[T; N]`）の値としての使用はエラー
- 関数とは `&[T; N]` で受け渡す。要素数 `N` は型の一部なので、ポインタ経由でも範囲検査が働く

## 7. 定数（const）とグローバル変数（static）

```
const N: usize = 5;
const LIMIT: i64 = N as i64 * 10 + 1;
static COUNT: i64 = 0;
static TABLE: [i64; 5] = [0; 5];
static P: &i64 = &TABLE[2];

fn bump() { COUNT = COUNT + 1; }
```

| | const | static |
|---|---|---|
| 実体 | メモリを持たず、使う箇所に値を埋め込む | 静的領域（`.data`）に置く |
| 型 | 整数・bool・`()` | 整数・bool・`()`・ポインタと、それらを要素とする配列 |
| 代入 | 不可 | 可（常に書き換え可能。`static mut` は無い） |
| `&` | 不可 | 可（`&COUNT`、`&TABLE`。関数から返してもよい） |

- 型注釈は必須。ポインタ型の const は書けない
- 初期値は**定数式**で、コンパイル時に評価する。定数式に書けるのは、リテラル（`true`/`false`/`()` を含む）、同じソースで定義した const、単項 `-`/`!`、`+ - * /`、比較、`as`、括弧。static の配列は `[c1, c2, ...]` / `[c; N]`（各要素が定数式）
  - static の参照・関数呼び出し・`&`/`*`・添字は書けない
  - const 同士の循環参照、定数式のゼロ除算はコンパイルエラー
  - 型の規則（暗黙の型変換をしない）・ラップアラウンドは通常の式と同じ
- ポインタ型の static（とその配列の要素）の初期値は、**アドレスの定数**：同じソースで定義した static の `&X` か、static の配列の要素の `&T[i]`（i は定数式。コンパイル時に範囲を検査する）
  - `static PS: [&i64; 2] = [&A, &B];`、`static PP: &&i64 = &P;` のようにも書ける
  - const のアドレス（`&N`）、ローカル変数のアドレス、`&*P` などは書けない
- static へ `&ローカル変数` / `&ローカル配列[i]` を直接代入するとエラー（`P = &x;`、`PS[0] = &a[1];`。関数から戻るとダングリングポインタになるため）。中間変数やポインタを経由した代入は検出しない
- fn・const・static は同じ名前空間を共有する。同名はエラー
- static の配列は、ローカルの配列と同じく添字でアクセスでき（範囲検査も同じ）、`&[T; N]` で関数に渡せる

## 8. 複数ソースファイル

```
import "lib/util.sl";
```

- ソースの先頭に `import "相対パス";` を書くと、そのソースに定義された fn・const・static を使える
- パスは import を書いたソースのディレクトリからの相対パスで、拡張子は `.sl`
- 取り込むのは**直接** import したソースの定義だけ（import 先がさらに import しているソースの定義は使えない）。import 先の `main` は取り込まない
- 自ソースと import 先、または import 先どうしで同名の定義（fn・const・static）があるとエラー。import の循環は許される
- 定数式からは import した const を参照できない（fn の本体からは参照できる）
- 名前空間は無く、fn 名・static 名がそのままリンク時のシンボル名になる。リンクする全ソースで fn・static が重複するとエラー（const はシンボルを持たないので、import で同時に見えなければ重複してよい）
