# 配列へのポインタ（`&[T; N]`）と関数での受け渡しにおける設計上の考慮点

step019 の配列はローカル変数専用で、`&a` や関数の引数・戻り値での使用を禁止していた。今回は配列へのポインタ型 **`&[T; N]`** を許可し、ポインタを通じて関数との間で配列を受け渡しできるようにする。あわせて代入文の左辺を一般化し、`p[i] = v;`・`(*p)[i] = v;`・スカラーの `*p = v;` を書けるようにする。

```
fn fill(p: &[i32; 3], v: i32) -> i32 {
    p[0] = v;
    p[1] = v;
    (*p)[2] = v;
    0
}
fn pick(a: &[i32; 3], b: &[i32; 3], first: bool) -> &[i32; 3] {
    if first {
        return a;
    }
    b
}
let x = [0i32; 3];
let y = [9i32; 3];
let d = fill(&x, 5);
let r = pick(&x, &y, false);
x[0] + r[2]    // 14
```

## 0. 方針として確定した事項

| 項目 | 決定内容 |
|---|---|
| 配列へのポインタ | `&a` で `&[T; N]` 型の値を得られる。`&&[T; N]` や `[&[T; N]; M]`（配列へのポインタの配列）も可。ネストした配列 `[[T; N]; M]` は引き続き不可 |
| 関数の引数 | `&[T; N]` を受け取れる。型注釈を省略した場合は、呼び出し側の `f(&a)` から推論される |
| 関数の戻り値 | **ポインタのみ**（`-> &[T; N]`）。配列の値返し（`-> [T; N]`）は引き続き不可 |
| 添字アクセス | `p[i]`（**自動デリファレンス**）と `(*p)[i]` の両方。読み出しにも代入にも使える |
| 代入 | 左辺を場所式に一般化した（`a[i]`・`p[i]`・`(*p)[i]`・`*p`） |
| ダングリング | return 式・末尾式が**直接** `&ローカル` を返す形を**簡易検査**でコンパイルエラーにする |
| 長さ | 型の一部。`&[i32; 3]` と `&[i32; 4]` は別の型（任意長のスライス `&[T]` は対象外） |

## 1. 考慮点

### 1.1 ダングリングポインタ

配列（を含む全ての変数）はスタック上のローカル変数としてしか存在しない。関数が自分のローカル変数を指すポインタを返すと、関数から戻った時点でそのスタックフレームは破棄され、ポインタは無効な領域を指す。

```
fn make() -> &[i32; 3] {
    let a = [1i32, 2i32, 3i32];
    &a           // 戻った時点で a は破棄される
}
```

この問題は step012 以降のスカラーのポインタにも元からあった（`fn f() -> &i64 { let x: i64 = 1; &x }` もコンパイルが通っていた）。配列を関数とやり取りする今回の拡張で起きやすくなるため、検査を導入した。

| 選択肢 | 評価 |
|---|---|
| ライフタイム（Rust） | 完全に防げるが、型システムへの導入が大掛かり |
| **簡易検査（採用）** | return 式・末尾式が直接 `&x`（x はローカル変数または仮引数）または `&a[i]`（a はローカルの配列）なら、エラーにする。典型的な誤りを低コストで防げる |
| 検査なし（C） | 未定義動作のまま |

簡易検査は「式の形」だけを見るため、次のように中間変数を経由した場合は**検出できない**（未定義動作のまま）。

```
fn f() -> &i64 {
    let x: i64 = 1;
    let p = &x;
    p            // 検出されない
}
```

`&*p`・`&p[i]`（p はポインタ）・`p` は呼び出し元のデータを指すため、許可する。仮引数もスタック上のローカル変数（レジスタからスピルされたもの）なので、`&仮引数` を返すのはエラーとする。暗黙の main は呼び出し元に戻らないため、検査の対象外とする。

### 1.2 戻り値を値で返さない理由

配列を値で返すには、x86-64 SysV の慣習（呼び出し元が戻り先の領域を確保し、隠しポインタで渡す sret）に相当する仕組みと、配列のコピー（`let b = f();`）が必要になる。1.1 の制約があるため、意味のある使い方は「呼び出し元が配列を用意し、関数に書き込ませる（出力引数）」形に集約できる。値返しはこの出力引数のシンタックスシュガーにすぎないので、今回は見送った。

### 1.3 スライス `&[T]` を対象外にした理由

長さが型の一部なので、`&[i32; 3]` を受け取る関数に `&[i32; 4]` は渡せない（任意長の `sum` は書けない）。これを解決するのはスライス（先頭ポインタと長さの組）だが、16バイトの値になり、「全ての値は操作スタック上の8バイトの1スロット・1レジスタ」というコード生成の前提が崩れる。そのため、将来の課題とする。

## 2. 構文

```
place-assign-stmt ::= expr '=' expr ';'
type              ::= '&' type | '[' type ';' INT ']' | ...（'&' '[' ... の制限を削除）
```

- `SAssignIndex String Expr Expr` を **`SAssignPlace Expr Expr`** に置き換えた。`x = v;`（`SAssign`）は従来どおり
- 文の判別: キーワードにも `IDENT '='` にも該当しない場合は、式を試しにパースし、次が `=` なら `SAssignPlace` とする。そうでなければ（パースに失敗した場合も含め）文はないものとして戻り、末尾式として改めてパースする（エラーもそちらで報告される）。これで step019 の `IDENT '['` 専用の試し読みは不要になった
- 左辺が場所式（`Index`/`Deref`）かどうかはコンパイル時に検査する（`5 = 1;` は `invalid left-hand side of assignment`）
- 優先順位は step019 のまま（添字は単項演算子より強い）。そのため、`*p[1]` は `*(p[1])` であり、`(*p)[1]` とは異なる

## 3. 意味論

### 3.1 場所式（lvalue）

`addressOf` が、場所式の実効アドレスを積む命令列と参照先の型を返す。`&e` と代入の左辺の両方で使う。

| 場所式 | アドレス | 型 |
|---|---|---|
| `x`（配列を含む変数） | `LoadAddr off` | x の型 |
| `*e` | e の値 | e が指す型 |
| `base[i]` | `indexAddr` | 要素型 |

step019 の `cannot take address of array` は削除した（`&a :: &[T; N]`）。

### 3.2 添字の基底（`arrayBase`）

`indexAddr` の基底部分を `arrayBase` として切り出し、配列へのポインタに対応させた。

| 基底 | 先頭アドレス |
|---|---|
| `a`（`[T; N]` 型の変数） | `LoadAddr off` |
| `(*e)`（e: `&[T; N]`） | e の値 |
| `e`（`&[T; N]` 型の任意の式。`p`、`f(&a)`、`ps[0]` など） | e の値（**自動デリファレンス**） |

その後の添字の usize 検査・`IBoundsCheck N`・`Push size; IMul W64; IAdd W64` は step019 のまま。要素数 N は型 `&[T; N]` から得られるため、**ポインタ経由でも範囲検査ができる**（リテラル添字のコンパイル時検査も同様）。

### 3.3 代入 `SAssignPlace lhs rhs`

```
addressOf lhs ++ compileExprTyped 型 rhs ++ [StoreInd 幅]
```

step019 で配列要素への書き込み用に導入した `StoreInd` をそのまま使うため、**新しい命令は不要**だった。スカラーの `*p = v;` も同じ仕組みで実現される。左辺の型が配列（`*p = [1, 2];`）なら、配列全体の代入としてエラーにする。

### 3.4 配列は値ではない（継続）

`*p`（p: `&[T; N]`）は配列型の式だが、配列のコピーになるため、値としては使えない（`let b = *p;`、末尾式の `*p` など）。添字の基底（`(*p)[i]`）と `&*p` でのみ使える。

### 3.5 関数シグネチャ

トップレベルが `[T; N]` の仮引数・戻り値は引き続きエラー（`... (pass &[T; N] instead)` と案内する）。`&[T; N]` は可。型推論（`resolveExprType`）の `Index` は、基底が `TArray t _` でも `TPtr (TArray t _)` でも要素型 `t` を返す。

## 4. エラーメッセージ

| ケース | メッセージ |
|---|---|
| ローカルへのポインタを返す | `cannot return reference to local variable: x` |
| 場所式でない左辺 | `invalid left-hand side of assignment` |
| `*p = [..]`（配列全体） | `cannot assign to array; assign to elements instead` |
| `*p`（配列）を値として使う | `array cannot be used as a value: dereferenced array pointer` |
| 配列型の仮引数・戻り値 | `array type is not allowed in function signature (pass &[T; N] instead): f` |
| 長さ・要素型が異なるポインタ | `type mismatch: expected &[i64; 3], found &[i64; 4]` |
| 配列でないポインタへの添字 | `cannot index into a value of type &i64` |

## 5. テストへの影響

- step019 の `SAssignIndex` のテストは `SAssignPlace (Index ...)` に置き換えた。`&a`・配列へのポインタ型をエラーとしていたテストは削除し（今回から許可）、シグネチャのエラーメッセージを更新した
- 追加したテスト:
  - parse: 配列へのポインタ型、ポインタの配列、`(*p)[i] = v;`、`*p = v;`、末尾式 `(*p)[0]` / `*p` が代入と誤認されないこと、末尾式のパースエラーの報告
  - 命令列: `&a`、`p[i]`（`Load W64` 起点）、`(*p)[i]` と `p[i]` が同一であること、`*p = v`
  - 意味論エラー: 4章の各ケース（ダングリングは末尾式・return 文・配列・配列要素・仮引数）、および返してよいもの（`&*p`・`&p[i]`・`p`）
  - Integration: 出力引数、ポインタ経由の合計（仮引数の型推論）、ポインタを返して呼び出し側で添字アクセス（`f(..)[i]` を含む）、u32/bool 配列、ポインタの配列、要素へのポインタを返して `*q = v`、スカラーの `*p = v`、`%p` 出力、ポインタ経由の実行時範囲外
- サンプル: `sample/samp020-0〜3.sl`
