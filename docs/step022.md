# 暗黙の main の廃止と `fn main()` の明示的な定義における設計上の考慮点

step009 以降、プログラムは「fn 定義とトップレベルの文の列＋末尾式」で構成され、トップレベル部分が暗黙の main だった。そのため main だけが特殊な扱いになっていた（`return` が使えない、`main` という関数名は予約、型推論・コンパイルの処理が「全 fn ＋暗黙 main」の二本立て）。今回、Rust と同じく **`fn main()` を明示的に定義する形**に統一する。

```
fn add(a, b) { a + b }
fn main() {
    let x = add(1, 2);
    if x > 2 {
        return x * 10;   // main でも return できる
    }
    x
}
// → 30
```

## 0. 方針として確定した事項

| 項目 | 決定内容 |
|---|---|
| トップレベル | `fn` 定義のみ。文・式は書けない（`expected 'fn' at top level, got: ...`） |
| 出力 | **main の戻り値**を、従来の暗黙 main の末尾式と同じ規則で表示する（`()` なら何も出力しない） |
| main の存在 | 必須で1個だけ（無ければ `missing function: main`、2個以上は既存の `function already declared: main`） |
| main の引数 | なし（`main function must not take parameters`） |
| main の呼び出し | 不可（`cannot call main`）。再帰・他の関数からの呼び出し・式文のいずれも |
| main の戻り値型 | 表示できる全ての型（整数・bool・`()`・ポインタ）。配列は全 fn 共通の既存の検査で不可 |
| 戻り値型の注釈 | 省略可。他の fn と同じく return 文・末尾式から推論する |
| main の `return` | 使える（早期 return した値も表示される） |
| ダングリング検査 | main は対象外（1.4） |
| 予約名 | `function name 'main' is reserved` は廃止 |

## 1. 考慮点

### 1.1 結果の出力方法

| 選択肢 | 評価 |
|---|---|
| **main の戻り値を表示（採用）** | 出力の仕組み（型ごとの printf の epilogue）をそのまま使える。暗黙 main の末尾式が main の末尾式に変わるだけなので、既存のプログラム・テストは構文の書き換えだけで移行できる |
| Rust 準拠（main は `()`、表示は `print` 組み込み関数） | 複数回の出力ができるが、組み込み関数の型付け・コード生成の追加と、全テスト・サンプルの末尾式を `print` 呼び出しへ書き換える必要があり、変更が大きい |
| C 準拠（戻り値を終了コードに） | 表示できる値が 0〜255 に限られ、テストも終了コードでしか検証できない |

`print` 組み込み関数は将来の課題とした（backlog）。

### 1.2 main の制約とその理由

| 制約 | 理由 |
|---|---|
| 引数なし | main の呼び出し元は C ランタイムだけで、引数を渡す経路が無い（`argc`/`argv` に相当する型も無い） |
| 呼び出し不可 | main の命令列の末尾は「戻り値を表示して終了する」epilogue で、通常の関数のように `ret` で値を返さない。呼び出せるようにすると、main だけ二通りの末尾が必要になる |
| 戻り値型は表示できる全ての型 | 暗黙 main の末尾式と同じ範囲。ポインタは `%p` で表示する（アドレスは実行のたびに変わるため、テストでは先頭の `0x` だけを確認している） |
| 戻り値型の注釈は省略可 | 他の fn と同じ規則。main には呼び出し元が無いため、仮引数の推論は起きず、戻り値型は自身の return 文・末尾式だけから決まる（`fn main() { 1 }` は i64、`fn main() {}` は `()`） |

### 1.3 main も通常の関数としてコンパイルする

main も他の fn と同じく `compileFnDecl` でコンパイルし、戻り値型は `resolveFnSigs` が確定させた `fnSigs` から取得する。これにより次の処理から暗黙 main 専用の分岐が無くなった。

- `resolveFnSigs`/`resolveSlots`/`programEvidence`: 暗黙 main の文・末尾式を別に走査していた処理を削除（main も `fnDeclEvidence` で他の fn と同様に証拠を集める）
- `collectEvidenceStmts`: 「関数の外（暗黙 main）なら return の証拠を集めない」分岐を削除（現在の関数名は常にある）
- `compileProgram`: 暗黙 main 用の `compileStmtsFrom` 呼び出しを削除し、コンパイル済みの fn の列から main を取り出す

`compile` の戻り値の形 `([(関数名, 命令列)], mainの戻り値型, mainの命令列)` は変えていないため、`CodeGen` と `app/Main.hs` は変更不要だった。main の命令列は他の fn と同じく末尾に関数末尾ラベル（`.Lfn_endN`）を持ち、main の中の `return` はそこへジャンプしてから表示の epilogue に合流する。

`return used outside function` は全ての文が fn 本体の中にあるため到達不能になったが、ブロック・if・while の再帰の形を変えないよう `ReturnCtx` の `Maybe` は残した。

### 1.4 ダングリング検査から main を除外する

step020 の簡易検査（return 式・末尾式が直接 `&ローカル` を返すとエラー）は、関数から戻るとスタックフレームが破棄されることが理由だった。main の戻り値は main 自身のフレームが残っている間に表示されるため、ダングリングにならない。暗黙 main は元々検査の対象外だったので、それを引き継いで main を除外した（`ReturnCtx` に関数名を持たせ、`checkNoLocalRef` が `"main"` なら何もしない）。

## 2. 構文

```
program ::= fn-decl*
```

- `type Program = [FnDecl]`（従来は `([FnDecl], [Stmt], Expr)`）
- `parseTopLevel`（fn 定義と文の混在を読む処理）と、プログラム全体の末尾式の省略を `()` へ脱糖する処理（step021）は削除した。fn 本体の末尾式の省略（step021）はそのまま main にも適用される

## 3. 移行

- **サンプル**（`sample/*.sl`）: トップレベルの文・末尾式を `fn main() { ... }` で包み、fn 定義はそのまま残す使い捨てスクリプトで全ファイルを変換した。変換前後で全サンプルの出力が一致することを確認した（`%p` のアドレスを除く）
- **テスト**:
  - ソース文字列（約350件）は同じスクリプトで変換した
  - トークン列の parse テストは、トークン列を `fn main() { ... }` で包んでパースする `parseMain` に置き換えた。パース結果は `splitMain`（`(main 以外の fn, main の文の列, main の末尾式)` に分解するヘルパー）で比較するため、期待値の形は従来のままにした
  - main の命令列の末尾に関数末尾ラベルが付くようになったため、命令列を比較するテストの期待値に `Label ".Lfn_endN"` を追加した。テスト用 VM（`run`）はラベルを何もしない命令として扱うようにした
  - 意味が変わったテスト: `function name 'main' is reserved`・関数の外での `return` のテストは削除。暗黙 main の末尾式で配列を値として使うテストは、main の戻り値型が配列になってシグネチャの検査に先に引っかかるため、式文（`a;`）で検査するようにした
- 追加したテスト:
  - parse: fn 定義の列、空のプログラム、トップレベルの文・式のエラー
  - compile: main なし・重複・引数あり・呼び出し（再帰・他の関数から・式文）のエラー、戻り値型の推論（サフィックス付きリテラル・無型リテラル・末尾式なし・return と末尾式の両方）、注釈との不一致、return と末尾式の不一致、ポインタを返せること、main が他の fn の命令列に含まれないこと
  - Integration: main からの早期 return（する場合・しない場合）、`-> i32` の明示、`return;` で何も出力しない、ローカル配列へのポインタを `%p` で表示、main より後に定義した関数の呼び出し

## 4. スコープ外（将来の課題）

- `print` 組み込み関数（複数回の出力。main を Rust と同じ `()` を返す関数にできる）
- グローバル変数・定数（トップレベルに `let` を書けなくなったため）
