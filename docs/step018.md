# 符号なし整数型（u32/u64）の導入における設計上の考慮点

これまでの整数型は符号ありの`i32`/`i64`のみだった。今回は符号なしの**`u32`/`u64`**を追加し、加減乗除・比較を行えるようにする。符号あり⇔符号なしの変換は、`docs/step017.md`で導入したキャスト`as`で明示的に行う。

## 0. 方針として確定した事項

| 項目 | 決定内容 |
|---|---|
| 型の混在 | 従来どおりエラー（`1u32 + 1i32`、`u32`変数への`i32`値の代入、`u32`と`u64`の混在など）。暗黙の変換は行わない |
| 型変換 | `as`のみ（Rust準拠）。`i32`/`i64`/`u32`/`u64`の16通りすべてを許可する |
| 範囲外の演算結果 | **ラップアラウンド**（`1u32 - 2u32` = 4294967295）。既存のi32/i64の規則（`docs/step002.md`）、Rustのリリースビルド、Cの符号なし演算と同じ |
| 符号なしへの単項マイナス | コンパイルエラー（Rustと同じ）。`-x`（x: u32）、`-1u32`、`let x: u32 = -1;`のいずれもエラー |
| 型なしリテラルの既定値 | 変更なし（i64のまま）。`u32`/`u64`の文脈では無型リテラルがその型になる |
| 追加する命令 | `IZext32`・`IDivU Width`・`ICmpLtU`/`ICmpLeU`/`ICmpGtU`/`ICmpGeU` |

### 範囲外の扱いでラップアラウンドを選んだ理由

| 選択肢 | 評価 |
|---|---|
| ラップアラウンド | 既存の符号あり整数と規則が揃う。命令の追加も実行時コストもない |
| 実行時エラー（Rustのデバッグビルド） | 符号なしだけを検査し、符号ありはラップのままにすると規則が不揃いになる。両方を検査するなら、言語全体の方針変更として別ステップで扱うべき |
| 飽和（0で止める） | 直感的だが、主要な言語のどれでも標準の演算子ではない |

## 1. 型の表現

```haskell
data Signedness = Signed | Unsigned
data Type = TyInt Signedness Width | TBool | TPtr Type
```

- `TyInt Width`に符号の有無を追加した。`Width`（`W32`/`W64`）は引き続きレジスタ幅を表し、符号の有無とは独立している
- `LitTyped Int Signedness Width`・`Cast Expr Signedness Width`・`TIntSuffixed Int Signedness Width`も同様に拡張した
- 字句解析では`5u32`/`5u64`をサフィックス付きリテラルとして認識する（`5u32x`は従来どおり`TInt`＋`TIdent`）
- `u64`の最大値（18446744073709551615）は`Int`の範囲を超えるが、`read`が同じビットパターンの負数（-1）へラップするため、そのまま保持できる。`movabsq`で出力すれば正しい値になる

## 2. スタック上の不変条件と命令

64bitのオペランドスタック上での各型の表現（不変条件）は次のとおり。

| 型 | 表現 |
|---|---|
| i32 | 符号拡張済み（従来どおり） |
| **u32** | **ゼロ拡張済み** |
| i64/u64 | 64bitそのまま |

加算・減算・乗算は、下位ビットだけを見れば符号の有無で結果が同じになる。そのため、既存の命令（`IAdd W32`など）の後に正規化命令`IZext32`を1つ足すだけで実現でき、既存の命令は変更しない。

| 命令 | x86-64 | 用途 |
|---|---|---|
| `IZext32` | `popq %rax; movl %eax, %eax; pushq %rax` | u32の正規化（`ISext32`のゼロ拡張版） |
| `IDivU W32` / `IDivU W64` | `xorl %edx, %edx` ＋ `divl %ecx` / `divq %rcx` | 符号なし除算。ゼロ除算チェックは既存と同じ。符号なしでは最小値/-1の問題が起きないため、-1の特別扱いは不要 |
| `ICmpLtU`/`ICmpLeU`/`ICmpGtU`/`ICmpGeU` | `cmpq` ＋ `setb`/`setbe`/`seta`/`setae` | 符号なし比較。u32はゼロ拡張済みなので、幅によらず64bitで比較してよい |

型ごとに生成する命令列：

| 式 | i32 | u32 | i64 | u64 |
|---|---|---|---|---|
| `a + b`（`-`/`*`も同様） | `IAdd W32` | `IAdd W32, IZext32` | `IAdd W64` | `IAdd W64` |
| `a / b` | `IDiv W32` | `IDivU W32` | `IDiv W64` | `IDivU W64` |
| `a < b`（他の大小比較も同様） | `ICmpLt` | `ICmpLtU` | `ICmpLt` | `ICmpLtU` |
| 変数の読み出し | `Load W32` | `Load W32, IZext32` | `Load W64` | `Load W64` |
| `*p` | `LoadInd W32` | `LoadInd W32, IZext32` | `LoadInd W64` | `LoadInd W64` |
| `-a` | `INeg W32` | エラー | `INeg W64` | エラー |

- 等価比較（`==`/`!=`）は符号の有無によらず同じ命令でよい
- `Load W32`/`LoadInd W32`は符号拡張（`movslq`）で読むため、u32では読み出し後に`IZext32`で正規化し直す。正規化命令が1つ増える分は、「最適化しない」という既存の方針（`docs/step016.md`・`docs/step017.md`）に従って許容する
- 関数の引数（`StoreArg`）・戻り値はスタックスロットと`%rax`を経由するだけなので変更不要。仮引数の読み出し時に上記の`Load`の規則が適用される

## 3. キャスト（`as`）の変換規則

Rustの`as`と同じく、**ビットの再解釈**として定義する。

| 変換 | 意味 | 命令 | 例 |
|---|---|---|---|
| 同じ幅で符号だけ変える（i32⇔u32） | ビットパターンはそのまま | キャスト先の正規化命令 | `-1i32 as u32` = 4294967295、`4294967295u32 as i32` = -1 |
| 同じ幅で符号だけ変える（i64⇔u64） | ビットパターンはそのまま | なし | `18446744073709551615u64 as i64` = -1 |
| 縮小（64→32） | 下位32bitに切り詰め、キャスト**先**の符号で解釈する | キャスト先の正規化命令 | `4294967296u64 as u32` = 0、`2147483648i64 as i32` = -2147483648 |
| 拡大（32→64） | キャスト**元**の符号で拡張する（符号ありなら符号拡張、符号なしならゼロ拡張） | キャスト元の正規化命令 | `-1i32 as u64` = 18446744073709551615、`4294967295u32 as i64` = 4294967295 |

```haskell
castInstrs :: Signedness -> Width -> Signedness -> Width -> [Instr]
castInstrs _ _ dstSg W32 = [normalize32 dstSg]     -- 32bitへ: キャスト先の符号で正規化
castInstrs srcSg W32 _ W64 = [normalize32 srcSg]   -- 32→64: キャスト元の符号で拡張
castInstrs _ W64 _ W64 = []                        -- 64→64: 再解釈のみ
```

`normalize32`は`Signed`なら`ISext32`、`Unsigned`なら`IZext32`を返す。i32/i64同士の変換は`docs/step017.md`と同じ命令列になるため、この規則はstep017の一般化になっている。

## 4. 出力

末尾式の型が`u32`なら`%u`、`u64`なら`%lu`で`printf`する（`fmtU32`/`fmtU64`を追加）。

## 5. エラーメッセージ

| ケース | メッセージ |
|---|---|
| 符号なしへの単項マイナス | `cannot apply unary minus to unsigned type u32` |
| 型の混在（演算・比較） | `type mismatch: u32 and i32` |
| 型の不一致（代入など） | `type mismatch: expected u32, found i32` |
| キャスト先が整数型でない | `invalid cast target: only integer types (i32/i64/u32/u64) are allowed` |

## 6. その他の考慮点・スコープ外

- **混在比較の罠を型で回避できる**: Cでは`-1 < 1u`が`-1`の符号なしへの変換により偽になる。今回は型の混在をコンパイルエラーとするため、この罠は起きない
- **範囲外の型付きリテラルが正規化されない（既存の癖）**: `5000000000u32`のように範囲外の型付きリテラルは、`Push`の値がそのままスタックに載る（i32の`5000000000i32`と同じ既存の挙動）。変数へ代入すれば`Store W32`で切り詰められるが、比較に直接使うと正しく比べられない。リテラルの範囲検査やコンパイル時の正規化は別のステップで扱う
- **検査付きの演算・変換**（Rustの`checked_sub`/`try_from`相当）、**ビット演算・シフト**（符号なしと相性が良い）は将来の拡張とする

## 7. テストへの影響

- 既存テストは`TyInt W32`→`TyInt Signed W32`のように構築子の引数を機械的に置き換えただけで、命令列の期待値は変わらない
- 追加したテスト：
  - 字句解析・構文解析：`u32`/`u64`のサフィックス、型注釈、キャスト
  - 命令列：u32の算術・読み出し・デリファレンス、符号なし除算・比較、キャストの組み合わせ
  - エラー：型の混在、単項マイナス
  - VM：`IZext32`・`IDivU`・`ICmp*U`
  - CodeGen：`movl %eax, %eax`・`divl`/`divq`・`setb`系・`%u`/`%lu`
  - Integration：アンダーフロー・オーバーフローのラップ、符号なし除算・比較、キャスト、関数の引数と戻り値、`&u32`、ゼロ除算
- サンプル: `sample/samp018-0〜3.sl`
