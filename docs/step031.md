# 引数の個数の上限（6個）の撤廃における設計上の考慮点

これまで、fn の仮引数は最大6個だった。SysV AMD64 ABI でレジスタ渡しになる分（`%rdi` `%rsi` `%rdx` `%rcx` `%r8` `%r9`）だけを実装し、スタック経由の引数渡しを見送っていたためである（step009、backlog「7個以上の引数（スタック経由の引数渡し）」）。7個以上の仮引数を書くと `too many parameters (max 6): f` になっていた。

今回、7個目以降を ABI どおりスタックで渡すようにし、上限を撤廃する。将来のスライス `&[T]`（1引数で2レジスタを使う）でも、レジスタの数がすぐに足りなくなるので、その前提を先に整える。

```
fn digits(a: i64, b: i64, c: i64, d: i64, e: i64, f: i64, g: i64, h: i64) -> i64 {
    (((((((a * 10 + b) * 10 + c) * 10 + d) * 10 + e) * 10 + f) * 10 + g) * 10 + h)
}

fn main() -> i64 {
    digits(1, 2, 3, 4, 5, 6, 7, 8)     // 12345678
}
```

## 0. 方針として確定した事項

| 項目 | 決定内容 |
|---|---|
| 上限 | なし（Rust と同じ）。`too many parameters` のエラーを削除する |
| 1〜6個目 | 従来どおりレジスタで渡す |
| 7個目以降 | SysV AMD64 ABI どおりスタックで渡す。call の時点で7個目が `(%rsp)`、8個目が `8(%rsp)`…。後片付けは呼び出し元が行う |
| 評価順 | 従来どおり左から右（Rust と同じ）。ABI の配置に合わせるために評価順を変えることはしない |
| 6個以下の呼び出し | 生成コードは従来と同一 |
| C との互換 | ABI どおりなので、C から7個以上の引数で pub fn を呼び出せる |

## 1. 考慮点

### 1.1 操作スタック上の並びが ABI と逆になる

実引数は左から右へ評価して操作スタックに積むので、最上段（最下位アドレス）が最後の引数になる。一方 ABI は、7個目の引数が最下位アドレスにあることを要求する。そのままでは並びが逆になる。

| 選択肢 | 評価 |
|---|---|
| 実引数を右から左へ評価する | 並べ替えが不要になる。しかし、副作用（static やポインタ経由の書き込み）の順序が変わり、Rust（左から右）と異なる |
| **スタック渡しの分を複製して並べ直す（採用）** | 最後の引数から順に `pushq off(%rsp)` で複製すると、7個目が最下位に来る。複製は7個目以降の個数だけで済み、変更が呼び出し（`genCall`）に閉じる |

レジスタ渡しの分は、複製の後に元の位置から `movq off(%rsp), reg` で読む。call から戻ったら、複製・パディング・元の n 個をまとめて `addq` で捨て、戻り値を積む。元の n 個も捨てるので、`stackDelta (ICall _ n) = 1 - n` は従来のままでよい。

### 1.2 アライメントのパディングの位置

ABI は、call の時点で `%rsp` が16バイト境界にあることを要求する（gcc でコンパイルされた関数は、SSE の `movaps` などでこれを前提にする）。操作スタックは8バイト単位なので、深さが奇数なら8バイトのパディングで揃える（step009）。

従来はパディングを call の直前に入れていた。しかし、スタック渡しの引数は call の時点で `%rsp` の真上になければならないので、call の直前に入れると引数との間に隙間ができ、呼ばれた側がパディングを7個目として読んでしまう。

```
正しい配置              call の直前にパディングした場合（誤り）
 ...                     ...
 8個目  8(%rsp)          8個目  16(%rsp)
 7個目  (%rsp) ← call    7個目  8(%rsp)
                         pad    (%rsp)  ← 7個目として読まれる
```

そのため、7個以上の呼び出しでは、パディングを**複製より先に**積む。call の時点の深さは「元の深さ（n 個の引数を含む）＋パディング＋複製の個数 k」なので、元の深さ＋k が奇数のときにパディングを入れる。

### 1.3 呼ばれた側での7個目以降の扱い

7個目以降は、呼ばれた側のプロローグの後、戻り番地と退避した `%rbp` の上の `16(%rbp)`、`24(%rbp)`… にある。

| 選択肢 | 評価 |
|---|---|
| その位置を仮引数の場所として直接使う | コピーが不要。しかし、正の `%rbp` 相対オフセットが `Load`/`Store`/`LoadAddr` と `frameSize` の計算に混ざる |
| **レジスタ渡しの分と同じくローカルのスロットへコピーする（採用）** | `StoreArg` の生成コードを変えるだけで、仮引数の割り付け（`allocParams`）やダングリングの検査（`&仮引数` はローカルを指す）をそのまま使える |

i32・bool の引数は、呼び出し元では操作スタック上の 64bit に正規化された値をそのまま8バイトで積む。呼ばれた側は下位32bit を `movl` で読む（レジスタ渡しの `argReg32` と同じ扱い）。

## 2. 構文・AST

変更なし。

## 3. コンパイラ・コード生成

- `Compiler.hs`：`maxParams` を削除し、`validateFnShapes` から引数の個数の検査を削除した
- `CodeGen.hs`
  - `genCall`：n ≤ 6 なら従来どおり（`popq` でレジスタへ取り出す）。n > 6 なら、k = n − 6、pad = （元の深さ＋k が奇数なら1、偶数なら0）として次を生成する
    1. pad = 1 なら `subq $8, %rsp`
    2. m = 0 .. k−1 について `pushq 8*(2m+pad)(%rsp)`（引数 n−1−m の複製。元の位置 `8*m` に、それまでのパディングと複製の分を足した位置）
    3. i = 0 .. 5 について `movq 8*(n−1−i+k+pad)(%rsp), argReg64 i`
    4. `call f`、`addq $8*(n+k+pad), %rsp`、`pushq %rax`
  - `StoreArg i w off`：i ≥ 6 なら `16 + 8*(i−6)(%rbp)` から `%rax`/`%eax` を経由してスロットへコピーする（`stackArgOffset`）。レジスタの一覧は `argRegs` にまとめた

## 4. 移行

- テスト「引数が7個を超える関数定義はエラー（レジスタ渡しの上限）」を削除し、7個以上でも実引数の個数の不一致はエラーになることのテストに置き換えた
- 既存のサンプルへの影響はない。`sample/samp031-0.sl` を追加した

## 5. スコープ外（将来の課題）

- C の関数の呼び出し（`extern "C"` 相当の宣言）：現在は simplang から C の関数を呼べないため、C との結合テストで確かめられるのは呼ばれる側（C の main から pub fn を呼ぶ）の ABI 互換だけで、呼び出す側の並べ替えとパディングは simplang どうしの結合テストと codegen の単体テストで確かめている
- スライス `&[T]`（先頭ポインタと長さの組）の引数渡しは、スライスの導入時に、1引数で2つの引数の位置を使う形として検討する
