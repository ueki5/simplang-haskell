# 変数・代入の導入における設計上の考慮点

現在の実装（単一の算術式 → 1つの `printf`）を、変数・代入をサポートする形に拡張する際に効いてくる設計ポイントを、パイプラインの各段階ごとに整理する。

## 1. 文法・構文（Lexer / Parser）

- **識別子トークンの追加**: `TIdent String` を追加し、字句解析に英字（+数字/アンダースコア）のスキャンを追加する必要がある。
- **プログラム＝単一の式、ではなくなる**: 現状 `parse :: [Token] -> Either String Expr` だが、代入や複数文を扱うには「文の並び」という概念が要る。区切り記号（`;` や改行）をどうするかも決める必要がある。
- **代入を式にするか文にするか**: `x = 5` を
  - (a) **式**として扱う（C言語的、`y = x = 5` のような連鎖や `(x = 5) + 1` が可能、右結合で最低優先順位の演算子として `parseExpr` に組み込む）
  - (b) **文**として扱う（`Expr` とは別に `Stmt = SAssign String Expr | SExpr Expr` を新設し、`Program = [Stmt]`）

  現状のパーサ構造（`parseExpr`/`parseTerm`/`parseFactor` の優先順位カスケード）に馴染むのは(a)ですが、テストのしやすさ・意味の分かりやすさは(b)が上です。

## 2. 意味論

- **宣言と代入の区別**: 明示的な `let x = ...` を要求するか、初回代入がそのまま宣言を兼ねる（動的言語的）か。前者は文法が増えるが未定義変数の扱いが明確になる。
- **未初期化変数の参照**: コンパイル時エラーにするなら、コンパイル時に「既知の変数集合」を引き回す簡易な静的チェックが必要（`compile` に環境を渡す）。
- **プログラムの出力対象**: 今は式1つの値を `printf` している。文の列になった場合、何を出力するか（最後の文が式ならその値、代入だけなら何も出さない、等）を決めないと `main` の生成ロジックが決まらない。

## 3. IR（`Instr`）とコンパイラ

- `Load String` / `Store String`（または解決済みオフセットを使う `Load Int` / `Store Int`）を `Instr` に追加。
- `compile :: Expr -> [Instr]` は環境（変数名→格納先）を必要とするため、シグネチャが `compile :: Env -> Expr -> ([Instr], Env)` のように状態を持ち回る形に変わる（Stateモナドを導入してもよい）。

## 4. コード生成（メモリ配置）— 一番大きな設計判断

変数の実体をどこに置くか:

- **スタック上のローカル変数**（`%rbp` 相対オフセット）: コンパイル時に `Map String Int`（名前→オフセット）を作り、変数の数だけ `subq $N, %rsp` でスタックを確保。関数呼び出しを見据えた「本物」の作り方だが、**System V ABI の16バイトアライメント**を `call printf` / `call exit` の前で維持する配慮が新たに必要（現状のプロローグは単純な `push %rbp; mov %rsp,%rbp` だけなので、ここが崩れると危険）。
- **グローバル変数**（`.bss` セクションに `varname: .zero 8` を静的に確保）: オフセット計算やアライメントを気にしなくてよく実装が単純。ただし将来関数やスコープを入れると再設計になる。

このプロジェクトが将来的にブロックスコープや関数を持つ方向なら前者、あくまで算術式の延長で変数を足したいだけなら後者が手早い。

## 5. VM（`run`、テスト用スタックマシン）

- `go :: [Instr] -> [Int] -> Either String Int` に加えて、変数の値を保持する `Map String Int` を引き回す必要がある。
- `Load`/`Store` の意味をVM側にも実装しないと、既存のHspecテスト方針（VM実行結果で検証）が使えなくなる。

## 6. テストへの影響

- Tokenizer: 識別子・複数文の区切りのケース
- Parser: 代入の優先順位・結合則、複数文
- CodeGen: `Load`/`Store` の命令列、スタック確保・アライメント
- Integration: `x = 1; y = 2; x + y` のような実プログラムをコンパイル・実行して検証

## 未決定事項

一番影響が大きいのは以下の2点。ここを先に決めておくと、パーサ・コード生成の作り方がブレない。

- **(A)** 代入を式として扱うか、文として扱うか
- **(B)** 変数をスタックローカルにするか、グローバルにするか
