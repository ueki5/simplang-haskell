# ドキュメント構成の見直し

これまでは各 step の設計を `docs/stepNNN.md` に、プログラム全体像（Key Design Notes）を `CLAUDE.md` に書いていた。
その結果、次の問題があった。

- `CLAUDE.md` が「プロジェクトの事実（仕様・実装）」と「作業の進め方」を兼ねており、本来の役割である作業手順・規約が書かれていなかった
- Key Design Notes は言語仕様と実装の詳細が1つの段落に混在していた（例：配列の項に構文上の制約とスタックオフセットの計算が並ぶ）
- `docs/step000.md`（アプリケーション仕様）は最初期の四則演算コンパイラのまま更新されておらず、最新の全体像は CLAUDE.md にしか無かった

挙動を変えない、ドキュメントだけの変更。

## 0. 方針として確定した事項

| 項目 | 決定内容 |
|---|---|
| 全体像の置き場所 | `docs/` 配下へ移し、次の3つに分ける：`language.md`（言語仕様）、`architecture.md`（実装の全体像）、`cli.md`（コマンドラインとビルド） |
| 全体像の文書の位置づけ | 常に main の最新の状態と一致させる。step を追加するたびに更新する |
| step 文書の位置づけ | その step で決めたこととその理由の記録。マージ後は書き換えない。撤回されたときだけ、冒頭と目次に注記する |
| step 文書の置き場所 | 現状のまま `docs/` 直下（過去のコミット・PR からのリンクを保つため） |
| 目次 | `docs/README.md` を新設し、CLAUDE.md にあった step 一覧を移す |
| `step000.md` | 初期仕様の記録として残し、冒頭に現在の仕様への参照を注記する |
| `CLAUDE.md` | プロジェクトの概要・コマンド・作業の進め方・規約だけを書く |

## 1. 移動した内容

| 移動元（CLAUDE.md） | 移動先 |
|---|---|
| ドキュメント一覧 | `docs/README.md` |
| Build & Run の引数説明 | `docs/cli.md` |
| Testing | `docs/architecture.md`「9. テスト」 |
| Key Design Notes のうち言語仕様にあたる部分（構文・型の規則・エラーになる条件・main の出力） | `docs/language.md` |
| Key Design Notes のうち実装にあたる部分（パーサ・型検査・環境管理・配列のアドレス計算・コード生成・ドライバ） | `docs/architecture.md` |
| Dependencies | `docs/architecture.md`「10. 依存パッケージ」 |

移すにあたり、ソースと照合して次の点を補った。

- `docs/language.md`：bool を返す main の出力（`true`/`false`）、終了コード、コメント構文が無いこと、すべての変数が再代入可能であること
- `docs/architecture.md`：`step000.md` 以降更新されていなかったパイプライン・モジュール・主要な型を最新化。テスト用 VM が扱わない命令を明記
- 撤回された step（step004・step015・step016）の冒頭に撤回の注記を追加

## 2. CLAUDE.md の構成

1. プロジェクトの概要と docs への参照
2. コマンド（ビルド・テスト・実行）
3. 作業の進め方（1 step = 1 機能のワークフロー）
4. ドキュメントの規約
5. 設計の規約
6. コーディング・テストの規約
