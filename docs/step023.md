# 関数シグネチャの型注釈の必須化（step015 の撤回）における設計上の考慮点

step015 で fn の仮引数型・戻り値型の注釈を省略できるようにし、`resolveFnSigs` が**プログラム全体の全 fn 本体**を走査する固定点ループで、仮引数型は呼び出し箇所の実引数から、戻り値型は自身の return 文・末尾式から推論していた。

この方式では、ある fn のシグネチャを確定させるのに「その fn を呼び出している全ての箇所」と「その fn の本体」が必要になる。将来の課題である**複数ソースからのビルド**（ソースごとにコンパイルし、他のソースの fn は宣言だけを頼りに呼び出す）では、別のソースにある呼び出し箇所・本体は見えないため、シグネチャが確定しない。そこで Rust と同じく、**関数シグネチャは宣言だけで確定する**規則に改める。

```
fn add(a: i64, b: i64) -> i64 { a + b }
fn reset(p: &i64) { *p = 0; }      // '->' を省略した戻り値型は ()
fn main() -> i64 {
    let x = add(1, 2);
    reset(&x);
    x
}
// → 0
```

## 0. 方針として確定した事項

| 項目 | 決定内容 |
|---|---|
| 仮引数の型注釈 | 必須（`expected ':' and type after parameter name: a`） |
| 戻り値型の省略 | Rust と同じく `-> ()` とみなす（推論はしない）。`-> ()` の明示も可 |
| 値を返す関数 | `-> T` の明示が必須。省略した関数が値を返すと型エラー（`type mismatch: expected (), found ...`） |
| main | 例外なし。値を表示する main は `fn main() -> i64 { ... }` と書く。省略時は `()` を返し何も出力しない |
| let の型推論（step014） | 変更なし。関数本体の中のローカルな推論はシグネチャの確定に影響しないため残す |
| 宣言順依存性 | 無し（従来どおり）。シグネチャは本体のコンパイル前に全 fn の宣言から一括で作る |

## 1. 考慮点

### 1.1 戻り値型を省略したときの扱い

| 選択肢 | 評価 |
|---|---|
| **`()` とみなす（採用）** | Rust と同じ。step021 で導入した `()` 型と自然につながり、値を返さない関数（`reset` のような出力引数の関数）を簡潔に書ける |
| 省略自体をエラー | 規則は単純だが、値を返さない関数にも毎回 `-> ()` を書く必要がある |

### 1.2 main も例外にしない

main は他の fn から呼び出せない（step022）ため、main の戻り値型だけは推論を残しても複数ソースのビルドの妨げにはならない。しかし、そのためだけに推論の仕組み（固定点ループ）を残すと例外規則になり、実装も大きいまま残る。全ての fn で同じ規則とし、推論の仕組みは丸ごと削除した。

## 2. 構文・AST

```
fn-decl ::= 'fn' IDENT '(' (IDENT ':' type (',' IDENT ':' type)*)? ')' ('->' type)? '{' stmt* expr? '}'
```

- `data FnDecl = FnDecl String [(String, Type)] Type Body`（step015 で導入した `Maybe` を外し、step014 以前の形に戻した）
- `parseParam` は `:` が無ければエラー、`parseFnDecl` は `->` が無ければ `TUnit` とする

## 3. コンパイラ

- `resolveFnSigs` を `buildFnSigs` に置き換えた。`validateFnShapes`（重複定義・最大6引数・main の存在と引数なし）の後、各 `FnDecl` の型をそのまま `FnSigs` に積み、配列型がシグネチャに含まれていればエラーとする
- 推論のための仕組みを全て削除した: `Slot`/`ResolvedSlots`/`LocalEnv`/`SlotResult`/`resolveExprType`/`addressOfSlot`/`callEvidence`/`collectEvidenceStmts`/`programEvidence`/`fnDeclEvidence`/`initialSlots`/`resolveSlots`/`resolveOne` など
- `compileFnDecl` は仮引数・戻り値の型を `FnDecl` から直接取得する
- `circular type inference: ...` エラーは発生しなくなった
- `compile` の戻り値の形は変えていないため、`CodeGen` と `app/Main.hs` は変更不要

## 4. 移行

- **テスト・サンプル**: 変更前のコンパイラ自身（非公開の `resolveFnSigs` と `typeName`）を使う使い捨てのツールで、省略されていた型注釈を推論結果のとおりに書き加えた（戻り値型の推論結果が `()` の場合は省略のまま）。`test/Spec.hs` は文字列リテラル単位で変換し、変換後・実装変更前にテストが全て通ること（挙動が変わっていないこと）を確認した。全サンプルの出力も変換前後で一致することを確認した（`%p` のアドレスを除く）
- **意味が変わったテスト**:
  - step015 の推論テスト（parse の `Nothing`、i64 デフォルト、呼び出し箇所からの推論、循環依存エラー、省略版の結合テスト）は削除
  - step022 の main の戻り値型推論テストは、注釈どおりになること・省略時は `()` になることのテストに置き換えた
  - main の末尾式で型の混在エラーを確認していたテストは、main の戻り値型が `()` になり先に別のエラーになるため、式文（`x + y;`）で確認するようにした
  - `compileAndRun`（AST を直接 main の本体にするテスト用ヘルパー）は main の戻り値型を引数で受け取るようにした
- **追加したテスト**: 仮引数の型注釈なしのエラー、`->` の省略と `-> ()` の明示がどちらも `TUnit` になること、戻り値型を省略した fn / main が値を返すとエラー、戻り値型を省略した fn の呼び出しは `()` 型

## 5. スコープ外（将来の課題）
