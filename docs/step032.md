# スライス `&[T]` と複数スロットの値における設計上の考慮点

step020 で、配列へのポインタ `&[T; N]` を導入した。要素数 `N` は型の一部なので、`&[i64; 3]` を受け取る関数に `&[i64; 5]` は渡せず、任意の長さの配列を受け取る関数は書けなかった。これを解決するのがスライス（先頭ポインタと長さの組）だが、16バイトの値になる。そのため、「全ての値は操作スタック上の8バイトの1スロット・1レジスタ」というコード生成の前提が崩れるとして、将来の課題にしていた（step020 §1.3、backlog「スライス `&[T]`」）。

今回、**値が複数のスロットを占められるように、コード生成を一般化**した上で、スライス `&[T]` を導入する。スライスは、ローカル変数・仮引数・戻り値として使える。この一般化は、将来のヒープ上の値（`Vec<T>` は (ptr, cap, len) の3スロット）の土台にもなる。

```
fn sum(s: &[i64]) -> i64 {
    let t = 0;
    let i = 0usize;
    while i < s.len() {
        t = t + s[i];
        i = i + 1;
    }
    t
}

fn longer(a: &[i64], b: &[i64]) -> &[i64] {
    if a.len() >= b.len() {
        return a;
    }
    b
}

fn main() -> i64 {
    let x = [1, 2, 3];
    let y = [10, 20, 30, 40, 50];
    let s = longer(&x, &y);       // &[i64; 3] も &[i64; 5] も &[i64] として渡せる
    sum(&x) + sum(s) + s.len() as i64   // 6 + 150 + 5
}
```

```
$ simplang-haskell main.sl -o prog && ./prog
161
```

## 0. 方針として確定した事項

| 項目 | 決定内容 |
|---|---|
| 型 | `&[T]`（AST は `TSlice T`）。`T` は今の配列の要素になれる型（整数・bool・()・ポインタ）。`[T]` 単独では使えない |
| 表現 | 先頭ポインタ ptr と長さ len（usize）の組。2スロット・16バイト。メモリ上は ptr が下位アドレス、len が `+8` |
| 使える場所 | ローカル変数（`let`、代入）・仮引数・戻り値 |
| 作り方 | **期待型が `&[T]` の箇所**（型注釈のある `let`、代入、実引数、戻り値）で、`&[T; N]` 型の式を自動的に変換する（Rust の unsized coercion）。`let s = &a;` のように期待型がなければ、従来どおり `&[T; N]` になる |
| 添字 | `s[i]` の読み出し・代入。実行時に len と比べて範囲を検査する（範囲外は `index out of bounds` で終了コード1） |
| 長さ | `s.len()`（usize）。配列 `a.len()` と配列へのポインタ `p.len()` にも使える（値は N）。メソッド呼び出しの構文は `len` だけを受け付ける |
| 引数渡し | スロットごとに引数の位置を割り当てる（ptr、len の順に2つ。Rust と同じ）。7個目以降のスタック渡し（step031）もスロット単位 |
| 戻り値 | ptr を `%rax`、len を `%rdx` で返す（SysV ABI・Rust と同じ）。fn の戻り値の型を codegen へ渡し、末尾でスロット数だけ pop する |
| 書き込み | `s[i] = v` を許可する（`&` と `&mut` を区別しない今の方針どおり） |
| 対象外 | static のスライス、スライスの配列・スライスのスライス、スライスへのポインタ `&&[T]`、部分スライス `&a[1..3]`、スライスどうしの比較、main の戻り値としてのスライス |

## 1. 考慮点

### 1.1 「1値＝1スロット」の前提の一般化

今のコード生成は、全ての値が操作スタック上の8バイトの1スロットに収まる前提で書かれている。これを、型ごとのスロット数 `slotCount :: Type -> Int`（`&[T]` は 2、それ以外は 1）で一般化する。

| 箇所 | 今 | 一般化した後 |
|---|---|---|
| 変数の読み出し・書き込み | `Load w off` / `Store w off` を1回 | スロットごとに `Load W64` / `Store W64` を繰り返す（`loadSlots` / `storeSlots`）。書き込みは最上段（len）から |
| 式文 `e;` | `IPop` を1回 | スロット数だけ `IPop` |
| 関数呼び出し `ICall name n` | n は実引数の個数。戻り値は1スロット | `ICall name 引数のスロット数 戻り値のスロット数` |
| 仮引数のスピル（`StoreArg i`） | i は仮引数の番号 | i はスロットの通し番号 |
| 戻り値 | `epilogueRet` で `popq %rax` | `epilogueRet` が戻り値の型を受け取り、2スロットなら `popq %rdx; popq %rax` |

スライスのためだけに「2スロットの値」を特別扱いせず、スロット数を型から求める形にしておく。そうすれば、`Vec<T>`（3スロット）を足すときに、この部分を作り直さずに済む。

操作スタックの深さ（`stackDelta`）と `call` 直前のアライメントの計算（step009, 031）は、もともとスロット単位で数えている。そのため、`ICall` のスロット数を正しく渡せば変更は要らない。

### 1.2 型を `TSlice T` とする

Rust の `&[T]` は、「unsized な型 `[T]` への参照」である。AST で `TPtr (TSliceUnsized T)` と表す案もあるが、この言語では `[T]` 単独の値・変数・`*s` を扱わないので、`&[T]` 全体を1つの型 `TSlice T` として表す。

| 書き方 | 扱い |
|---|---|
| `&[T]` | `TSlice T` |
| `[T]`（`&` なし） | パースエラー（`slice type must be used behind a reference: &[T]`） |
| `&&[T]` | パースエラー（`pointer to slice is not supported`）。式 `&s`（s がスライス）も同じエラー |
| `&[&[T]]`、`[&[T]; N]` | パースエラー（`slice of slices is not supported` / `array of slices is not supported`） |
| `&[[T; N]]` | 従来どおり `nested arrays are not supported` |
| `&[&[T; N]]` | 可（要素は8バイトのポインタ） |

### 1.3 `&[T; N]` → `&[T]` の変換をどこで行うか

| 選択肢 | 評価 |
|---|---|
| 明示的な変換（`&a[..]` や `a.as_slice()`） | 暗黙の変換をしない方針に沿う。ただし範囲の構文やメソッドが必要で、Rust でも普通は書かない |
| **期待型が `&[T]` の箇所で暗黙に変換する（採用）** | Rust の unsized coercion と同じ。規約の「暗黙の型変換をしない」は整数どうしの変換を念頭に置いたもので、Rust 自身が許している変換なので、「Rust の仕様に合わせる」を優先する |

変換は `compileExprTyped` の入口で1か所にまとめる（`coerceToSlice`）。期待型が `TSlice T` で、式の推論型が `TPtr (TArray T N)` なら、式を `&[T; N]` としてコンパイルし、`Push N` を続けて len とする。要素型が異なれば（`&[i32; 3]` → `&[i64]`）従来どおり `type mismatch` にする。後で `&Vec<T>` → `&[T]` を足すときも、この関数に変換元を加えるだけで済む。

型推論（`let s = &a;`）では変換しない（Rust と同じく `&[T; N]` になる）。`unifyType` も変更しない。

### 1.4 引数の位置の割り当て

スライスの仮引数は、ptr と len の2つの引数の位置を使う。レジスタが1つしか残っていない場合の扱いは、ABI の考え方で異なる。

| 選択肢 | 評価 |
|---|---|
| C の構造体と同じ（16バイトの構造体は、2レジスタが空いていなければ丸ごとスタックへ） | C との互換。ただし割り当ての規則が複雑になる |
| **スロットごとに独立に割り当てる（採用）** | Rust の `&[T]` の渡し方（2つのスカラーの引数として渡す）と同じ。ptr が `%r9`、len がスタックに分かれてもよい。今の `genCall` と `StoreArg` が、スロットの通し番号だけでそのまま動く |

C の関数とスライスをやり取りする手段はない（backlog「C の関数の呼び出し」）ので、C の構造体の規則に合わせる必要はない。

### 1.5 戻り値を `%rax:%rdx` で返す

SysV ABI では、16バイト以下の値を `%rax` と `%rdx` の組で返せる。Rust も `&[T]` を ptr = `%rax`、len = `%rdx` で返す。

`return e;` と末尾式は、従来どおり値を操作スタックに残して関数末尾ラベルへ合流する。そこから先の取り出し方を、どこで決めるかが論点になる。

| 選択肢 | 評価 |
|---|---|
| 2スロットの関数だけ、末尾ラベルの後に `IPopRetHi`（len を `%rdx` へ）という命令を足す | 1スロットの関数の命令列が今と同じなので、既存のテストは変わらない。しかし、戻り値の取り出しが命令列（2スロット目）と codegen（1スロット目）に分かれ、3スロット以上（sret）を足すときに、また別の仕組みが要る |
| **fn の戻り値の型を codegen へ渡し、`epilogueRet` がスロット数に応じて取り出す（採用）** | main が戻り値の型を codegen へ渡し、`epilogue` が型に応じて表示しているのと同じ形になる。戻り値の取り出しが `epilogueRet` の1か所にまとまり、sret もそこへ分岐を足すだけで済む。`cmFns` の形が変わるので、fn の命令列を比べる既存のテストや、fn を codegen へ渡すテストを直す |

既存のテストへの影響は大きいが、仕組みの素直さを優先した。

- `CompiledModule` の `cmFns` を `[(String, [Instr])]` から `[(String, Type, [Instr])]`（名前・戻り値の型・命令列）にする。`compile` の戻り値と `codegenModule` の引数も同じ形にする
- `epilogueRet :: Type -> [String]` は、1スロットなら従来どおり `popq %rax`、2スロットなら `popq %rdx`（最上段の len）・`popq %rax`（ptr）の後に `leave`・`ret` を出す

呼び出し側は、`call` の後に `pushq %rax` と `pushq %rdx` を行う。

### 1.6 範囲検査を実行時の長さで行う

`IBoundsCheck N` は、N がコンパイル時に決まる前提である。スライスの添字には、操作スタック上の len と比べる `IBoundsCheckDyn` を新設する。

```
基底を評価     → [ptr, len]
添字を評価     → [ptr, len, i]
IBoundsCheckDyn → [ptr, i]      i ≥ len（符号なし）なら .Lindex_error
Push 要素サイズ; IMul W64; IAdd W64 → [要素のアドレス]
```

基底がスライスの変数なら、`Load W64 off`（ptr）と `Load W64 (off+8)`（len）で積む。関数呼び出しなど任意の式でもよい（`longer(&x, &y)[0]`）。添字がリテラルでも、長さが実行時まで分からないので、コンパイル時の範囲検査はしない。

### 1.7 長さの取得 `s.len()`

| 選択肢 | 評価 |
|---|---|
| 組み込み関数 `len(s)` | 構文の追加は不要。しかし Rust と異なり、ユーザーが定義する `fn len` と名前が衝突する |
| **メソッドの構文 `s.len()`（採用）** | Rust と同じ。字句 `.` と、後置の `.IDENT(引数)` を追加する。今回は `len` だけを受け付けるが、将来の `v.push(x)` などに同じ構文を使える |

AST は一般的な形 `MethodCall Expr String [Expr]` とし、メソッド名と型の組み合わせはコンパイル時に検査する。

| 受け手の型 | `len()` の命令列 |
|---|---|
| `&[T]` の変数 | `Load W64 (off+8)` |
| `&[T]` の任意の式 | 式を評価 → `INip`（2段目の ptr を捨てる） |
| `[T; N]` の変数 | `Push N` |
| `&[T; N]` の式 | 式を評価 → `IPop` → `Push N`（式の副作用を残す） |

`INip` は「最上段を残して2段目を捨てる」命令として新設する。

### 1.8 ダングリング

ローカルの配列から作ったスライスを返すと、ダングリングになる。

```
fn bad() -> &[i64] {
    let a = [1, 2, 3];
    &a          // cannot return reference to local variable: a
}
```

今の簡易検査（`checkNoLocalRef` / `isLocalRef`）は、戻り値の式が直接 `&ローカル` であるかを見る。スライスへの変換は戻り値の式の形を変えないので、この形はそのまま検出される。`let s: &[i64] = &a; s` のように中間変数を経由する形は、従来のポインタと同じく検出しない（backlog 1.5）。

### 1.9 比較・キャスト・main の戻り値

- `s == t` などの比較は、Rust では要素どうしの比較になる。要素ごとの比較の命令列が必要なので、今回はエラーにする（`cannot compare slices`）。ptr どうしの比較と誤解されるのを防ぐ意味もある
- `as` は従来どおり整数型どうしだけ（`invalid cast`）
- main の戻り値は表示するだけで、スライスの表示形式（Rust の `[1, 2, 3]`）はまだ決めていない。そのため、`fn main() -> &[T]` はエラーにする（`invalid return type for main: &[i64]`）

## 2. 構文・AST

```
type    ::= '&' '[' type ']'           （新規。スライス）
          | '&' type | '[' type ';' INT ']' | ...（従来）
postfix ::= primary ( '[' expr ']' | '.' IDENT '(' (expr (',' expr)*)? ')' )*
```

- 字句：`.` を `TDot` として追加する
- `Type` に `TSlice Type` を追加する。`typeName` は `&[i64]` の形
- `Expr` に `MethodCall Expr String [Expr]` を追加する。優先順位は添字と同じ（最強）。そのため `&a.len()` は `&(a.len())`、`*p.len()` は `*(p.len())` になる（Rust と同じ）
- `parseTypeAnnotation` の `'&'` の分岐で、直後が `'['` なら要素型を読み、`']'` なら `TSlice`、`';'` なら従来の `TPtr (TArray ...)` とする。1.2 の表のエラーもここで出す

## 3. 意味論

- `slotCount :: Type -> Int`、`stackBytes (TSlice _) = 16` を追加する
- `compileExprTyped` の入口で `coerceToSlice`（1.3）を行う
- `Var s`（スライス）は `loadSlots`、`let`/代入/仮引数は `storeSlots` で、スロット数分の `Load`/`Store` に展開する
- `inferMaybeType`：`Index` の基底が `TSlice T` なら要素型 `T`、`MethodCall _ "len" []` は `TUsize`、`AddrOf` の参照先がスライスならエラー
- `indexAddr` の基底の解決（`arrayBase`）を、「静的な長さ N」か「実行時の長さ（スタック上の len）」のどちらかを返す形にし、後者のときは `IBoundsCheckDyn` を使う
- `compileCompare` で被演算子の型がスライスならエラー
- `buildFnSigs`：仮引数・戻り値にスライスを許す。`main` の戻り値の型がスライスならエラー
- static の型に `TSlice` は使えない（従来の `checkGlobalType` のまま `invalid type for static`）

## 4. コード生成

| 命令 | 生成コード | `stackDelta` |
|---|---|---|
| `ICall name n r` | `genCall` は n スロットを引数の位置へ割り当てる（step031 のまま）。call の後に `pushq %rax`、r = 2 なら続けて `pushq %rdx` | r − n |
| `IBoundsCheckDyn`（新規） | `popq %rax`（i）、`popq %rbx`（len）、`cmpq %rbx, %rax`、`jae .Lindex_error`、`pushq %rax` | −1 |
| `INip`（新規） | `popq %rax`、`addq $8, %rsp`、`pushq %rax` | −1 |

- `genBody` の `ICall` の深さの計算を `depth + r - n` にする
- `codegenModule` は fn ごとに (名前, 戻り値の型, 命令列) を受け取り、`epilogueRet` に戻り値の型を渡す（1.5）
- `frameSize` は `Load`/`Store` のオフセットから求めているので、変更は要らない（len の `off+8` は ptr の `off` より浅い）
- VM（`run`）は関数呼び出しに対応していないので、変更しない

## 5. 移行

- `ICall` の引数が増えるので、`ICall` を直接書いているテスト（compile の期待値・codegen の単体テスト）に戻り値のスロット数 `1` を加える
- `cmFns`・`compile`・`codegenModule` の fn の形が (名前, 戻り値の型, 命令列) に変わるので、fn の命令列を比べるテストと、`codegen`/`codegenModule` に fn を渡すテストを機械的に直す（直したのは12か所）
- 1スロットの関数の命令列と生成コードは変わらない
- `docs/language.md`：型（スライス）、式（`s.len()`、添字）、関数（引数・戻り値にスライス）、配列の章の「任意長は対象外」の記述を更新する
- `docs/architecture.md`：「1値＝1スロット」の記述を、スロット数による一般化に書き換える。スライスの添字・長さ・戻り値を追記する
- `docs/backlog.md`：「スライス `&[T]`」を実現済みへ移し、6 の課題を追記する
- サンプル：`sample/samp032-0.sl`（冒頭の例）を追加する。既存のサンプルへの影響はない

## 6. スコープ外（将来の課題）

| 課題 | 補足 |
|---|---|
| static のスライス（`static S: &[i64] = &T;`） | `.data` に2つの `.quad` を置き、`LoadGlobal`/`StoreGlobal` を2スロットに対応させる必要がある |
| スライスの配列・スライスのスライス（`[&[T]; N]`、`&[&[T]]`） | 16バイトの要素を扱えるよう、配列の要素サイズの前提（`storageWidth`）を一般化する必要がある。backlog「ネストした配列」と同じ種類 |
| スライスへのポインタ（`&&[T]`、`&s`） | `*p` の読み書きで、`LoadInd`/`StoreInd` を2スロットに対応させる必要がある |
| 部分スライス（`&a[1..3]`） | 範囲 `..` の構文と、開始 ≤ 終了 ≤ 長さの実行時検査が必要。範囲の構文は `for` 文と合わせて設計する |
| スライスどうしの比較（`s == t`） | 要素ごとの比較の命令列が必要。backlog「配列のコピー・比較」と合わせて検討する |
| main の戻り値としてのスライス | 表示形式（`[1, 2, 3]`）を決める必要がある |
| `len` 以外のメソッド | 今回はメソッド呼び出しの構文だけを入れ、受け付けるのは `len` のみ |
| 3スロット以上の値の戻り値（sret） | `Vec<T>` や配列の値返しで必要になる。backlog「配列の値返し」と同じ仕組み |
