# fnの型推論（step015）の内部関数解説

対象: `src/Compiler.hs` の fn 仮引数・戻り値型の推論（`resolveFnSigs` の1パス目）で使われる以下の関数。

- `chainSlot`
- `resolveExprType`
- `callEvidence`
- `resolveOne`

全体の流れは次のとおり。

```
resolveFnSigs
  └ resolveSlots（再帰処理で固定点ループ(未解決スロットが空になるまで繰り返し)）
      ├ programEvidence（プログラム全体を1回走査して証拠を集める）
      │   ├ fnDeclEvidence …  １つの関数に対して仮引数、本文、末尾式から証拠を集める
            ★ 全ての関数から証拠を集める(証拠１)
      │   │   ├ paramLocalscope … 関数引数から変数環境を取得
      │   │   ├ collectEvidenceStmts … 関数本文と前段で取得した変数環境より証拠を集める。
      │   │   ├ callEvidence … 関数末尾式の呼び出しから仮引数の証拠を集める
      │   │   └ resolveExprType … 関数末尾式から戻り値の証拠を集める
      │   │       └ chainSlot … SlotResult を連結する bind
      │   ├ collectEvidenceStmts … 本文(関数または暗黙main)を辿り証拠を集める。
            ★ 暗黙のmainの本文から変数環境、証拠を集める(証拠２)
      │   └ callEvidence … 末尾式中の呼び出し → ParamSlot の証拠
            ★ 暗黙のmainの末尾式、前段で取得した変数環境を元に証拠を集める(証拠３)
          ★ 証拠１、証拠２、証拠３を連結して返却
      └ resolveOne（スロット1個ごとに、このラウンドで型を確定できるか判定）
        ★ programevidencdが集めた証拠を元に未解決スロットを解決
```

## 1. `chainSlot`

`src/Compiler.hs:448`

```haskell
chainSlot :: SlotResult -> (Maybe Type -> SlotResult) -> SlotResult
chainSlot r k = do
  v <- r
  case v of
    Left slot -> Right (Left slot)
    Right ty -> k ty
```

### 前提：`SlotResult` は3通りの結果を表す

```haskell
type SlotResult = Either String (Either Slot (Maybe Type))
```

| 値 | 意味 |
|---|---|
| `Left err` | 型エラーが確定した（未宣言変数、bool/ポインタの不整合など） |
| `Right (Left slot)` | まだ決まっていない `slot`（省略された引数型や戻り値型）を**待っている**ので、今は結論が出せない |
| `Right (Right mty)` | 型が分かった（`Nothing` は型サフィックスなし整数リテラルだけの式） |

### やること

「前の計算 `r` の結果を見て、型が取れたときだけ続きの `k` を実行する」。

1. **`r` がエラー（`Left err`）の場合**：`do` の中の `v <- r` で `Either` モナドが止まり、エラーがそのまま返る。
2. **`r` がスロット待ち（`Right (Left slot)`）の場合**：`k` は呼ばずに、同じ待ち状態を返す。
3. **`r` で型が取れた（`Right (Right ty)`）場合**：`ty` を `k` に渡して計算を続ける。

`Either String` と `Either Slot` の2段になった型に対して、`>>=`（bind）を手書きしたもの。モナド変換子で書くと `ExceptT Slot (Either String) (Maybe Type)` の `>>=` にあたり、エラーと「待ち」のどちらでも処理が止まる。

### 使われ方（`resolveExprType` 内）

```haskell
combine a b =
  go a `chainSlot` \ta ->
    go b `chainSlot` \tb ->
      case unifyMaybeType ta tb of ...
```

`chainSlot` がないと、「エラーかどうか」と「待ちかどうか」を毎回 `case` で二重に分岐させる必要がある。`chainSlot` を使うと、左オペランドの型 `ta` と右オペランドの型 `tb` がそろったときだけ単一化に進む、という流れを素直に書ける。

他の使用箇所も同じ形。

- `Not e`：オペランドの型が分かったら、int でないことを確認して `TBool` を返す
- `Deref e`：オペランドの型が分かったら、`TPtr inner` から `inner` を取り出す
- `combineBool`：`combine` で両辺の整合を確認したあと、結果の型は捨てて（`\_ ->`）`TBool` を返す

### 動作上の特徴

- **最初に見つかった待ちスロットだけを返す**：`a` が待ちなら `b` は調べない。報告される依存は1つだけだが、固定点ループが毎ラウンド全体を走査し直すので問題ない。
- **エラーの報告が遅れることがある**：`a` が待ちのとき、`b` の中にある確定的なエラーはそのラウンドでは出ない。循環依存で止まった場合は、そのエラーより先に `circular type inference` エラーが出る可能性がある。
- **`Neg` には使っていない**：`go (Neg e) = go e` のように、結果をそのまま返すだけのところでは不要。

## 2. `resolveExprType`

`src/Compiler.hs:470`

```haskell
resolveExprType :: Map String FnDecl -> ResolvedSlots -> LocalEnv -> Expr -> SlotResult
```

**型注釈が一部まだ決まっていない状態のまま、1つの式の型を求める**関数。

### 位置づけ：`inferMaybeType` の「未確定を許す版」

`inferMaybeType`（`src/Compiler.hs:314`）の LocalEnv 版。式の型を決める規則は同じで、違うのは環境と結果の型。

| | `inferMaybeType` | `resolveExprType` |
|---|---|---|
| 使う時期 | `FnSigs` が確定した後（コード生成時） | `FnSigs` を確定させる途中（推論ループ） |
| 関数の型情報 | `FnSigs`（全部確定済み） | `fnDeclMap` ＋ `ResolvedSlots`（途中まで解決済み） |
| 変数環境 | `Env`（オフセット, 型） | `LocalEnv`（`Either Slot Type`：まだスロット待ちの変数もある） |
| 結果 | `Either String (Maybe Type)` | `SlotResult`＝`Either String (Either Slot (Maybe Type))` |

結果に「`Slot` 待ち」が1段増えている点が要。型がまだ決まっていないものに触れたら、エラーにはせず「このスロットが決まるまで保留」と返す。

### 引数

- `fnDeclMap`：関数名 → `FnDecl`。関数が宣言されているかの確認だけに使う
- `resolved`：これまでに型が決まったスロット。`initialSlots` の段階で、注釈が書かれている箇所も最初から入っている
- `env`：現在のスコープにあるローカル変数（仮引数・`let`）の状態。型が決まっていれば `Right ty`、未解決の仮引数スロットやそれに依存する `let` なら `Left slot`
- `expr`：型を求めたい式

### 各ケースの動き

**待ちが発生する入口は `Var` と `Call` の2つだけ。**

```haskell
go (Var name) = case lookupLocal name env of
  Nothing          -> Left ("undeclared variable: " ++ name)
  Just (Left slot) -> Right (Left slot)          -- 未解決の仮引数（またはそれ由来のlet）
  Just (Right ty)  -> Right (Right (Just ty))

go (Call name _) = case Map.lookup name fnDeclMap of
  Nothing -> Left ("undeclared function: " ++ name)
  Just _  -> case Map.lookup (ReturnSlot name) resolved of
    Just ty -> Right (Right (Just ty))
    Nothing -> Right (Left (ReturnSlot name))   -- 戻り値型が未解決
```

`Call` は `inferMaybeType` と同じく戻り値型だけを返し、実引数の型は見ない。実引数から仮引数の型を推論するのは `callEvidence` の役目。

**その他のケース**は `inferMaybeType` と同じ規則。子の結果は `chainSlot` でつなぐので、子が待ちなら親もそのまま待ちになる。

- `Lit` → `Nothing`（未確定の整数）、`LitTyped` / `BoolLit` / `ToI64` / `ToI32` → 確定した型
- `Neg` → 子の型をそのまま返す
- `Add` など算術演算 → `combine`：両辺の型を `unifyMaybeType` で単一化する（`i32` と `i64` が混ざればエラー）
- `Eq` / `Lt` など比較演算 → `combineBool`：両辺を単一化して整合を確認し、結果は `TBool`
- `Not` → int ならエラー、それ以外は `TBool`
- `Deref` → `TPtr inner` から `inner` を取り出す
- `AddrOf` → `addressOfSlot`（`addressOf` の LocalEnv 版）に任せ、結果を `TPtr` で包む

### 呼び出し元：何の「証拠」として使うか

結果は `Evidence`（対象スロットと、その証拠の組）としてまとめられ、固定点ループに渡される。呼び出し元は4か所。

1. **`callEvidence`**（`:556`）：`f(x, y)` の各実引数の型を、`ParamSlot f i` の証拠にする
2. **`SReturn`**（`:624`）：`return e` の型を、今いる関数の `ReturnSlot` の証拠にする
3. **`fnDeclEvidence`**（`:660`）：関数本体の末尾式の型を、その関数の `ReturnSlot` の証拠にする
4. **`SLetInferred`**（`:583`）：`let x = e;` の型を決めて `LocalEnv` に登録する。結果が待ちなら `x` 自身も `Left slot` として登録され、以降 `x` を参照すると同じスロット待ちになる。`Nothing`（リテラルのみ）なら `i64` にする

### 具体例

```
fn add(a, b) { a + b }
add(1i32, 2)
```

**1ラウンド目**

- `add` の末尾式 `a + b`：`a` が `ParamSlot add 0` 待ち → `ReturnSlot add` の証拠は「`ParamSlot add 0` 待ち」
- 呼び出し `add(1i32, 2)`：`ParamSlot add 0` の証拠は `Just i32`、`ParamSlot add 1` の証拠は `Nothing`
- → param#1 は `i32` に決まる。param#2 は `Nothing` しか証拠がないので `i64` になる（この結果は後段の型検査で不一致として検出される）

**2ラウンド目**

- 仮引数が `resolved` に入ったので、`a + b` はもう待ちにならず、実際に型を計算して単一化する

`resolveExprType` 自体は「今の情報で分かるところまで」を1回計算するだけ。待ちを繰り返し解消していくのは、外側の固定点ループの役目。

### 補足

- 待ちになったとき返すのは**最初に見つかったスロット1つだけ**（`chainSlot` の性質）
- 自分の `ReturnSlot` を待っている証拠（`fact` の自己再帰など）は、`resolveOne` で依存として数えずに無視される。`resolveExprType` 自身は自己参照かどうかを区別せず、単に待ちを返すだけ

## 3. `callEvidence`

`src/Compiler.hs:532`

```haskell
callEvidence :: Map String FnDecl -> ResolvedSlots -> LocalEnv -> Expr -> Either String Evidence

type Evidence = [(Slot, Either Slot (Maybe Type))]
```

式の中に出てくる**関数呼び出しをすべて探し、実引数の型を、呼ばれた側の仮引数スロット（`ParamSlot`）の証拠として集める**関数。

### なぜ必要か

fn の仮引数には初期化式がない。そのため、型の手がかりは**呼び出し側で渡された実引数**しかない（呼ばれる側の本体で仮引数がどう使われるかは見ない方針）。

### 構造：2つの処理

#### (1) 式の木をたどって `Call` を探す

`Call` 以外のケースは、子の式を再帰的にたどって結果を連結するだけ。

```haskell
go (Lit _)     = Right []          -- 葉：呼び出しなし
go (Var _)     = Right []
go (Neg e)     = go e              -- 単項：子をたどる
go (Add a b)   = combine a b       -- 二項：両辺の証拠を (++) で連結
go (ToI64 e)   = go e              -- ※ resolveExprType と違い、to_i64 の中もたどる
go (AddrOf e)  = go e
...
combine a b = (++) <$> go a <*> go b
```

ここでは**型の計算は一切しない**。`resolveExprType` の `ToI64 _` は中身を見ずに `i64` を返すが、`callEvidence` は `to_i64(f(x))` の中にある `f(x)` も見逃さないように、すべての子をたどる。

#### (2) `Call` を見つけたら証拠を作る

```haskell
go (Call name args) = do
  nested <- concat <$> mapM go args                 -- (a) 実引数の中にある呼び出し
  paramEv <- mapM
    (\(i, arg) -> (,) (ParamSlot name i) <$> resolveExprType fnDeclMap resolved env arg)
    (zip [0 ..] args)                               -- (b) この呼び出し自身の実引数
  pure (nested ++ paramEv)
```

- **(a)** `f(g(x))` のように、実引数の中にさらに呼び出しがある場合に備えて再帰する
- **(b)** i 番目の実引数の型を `resolveExprType` で求め、`(ParamSlot name i, 結果)` の組にする

`resolveExprType` の結果が「別のスロット待ち」の場合も、エラーにはせず**待ちのまま証拠として記録**する。それをどう扱うかは `resolveOne` が決める。

### 例

```
fn g(x) { x }
fn f(a, b) { a + b }
let y: i32 = 3;
f(g(y), 10)
```

暗黙 main の末尾式 `f(g(y), 10)` から集まる証拠（1ラウンド目）:

| 由来 | スロット | 証拠 |
|---|---|---|
| nested：`g(y)` | `ParamSlot g 0` | `Right (Just i32)` |
| `f` の第1引数 `g(y)` | `ParamSlot f 0` | `Left (ReturnSlot g)`（g の戻り値が未解決） |
| `f` の第2引数 `10` | `ParamSlot f 1` | `Right Nothing`（リテラルのみ） |

その後の流れ:

- 1ラウンド目：`g` の param#1 が `i32` に決まる。`f` の param#2 は `Nothing` だけなので `i64` にデフォルトされる
- 2ラウンド目：`g` の戻り値が `i32` に決まる
- 3ラウンド目：`f` の param#1 が `i32` に決まる

### 呼び出し元

証拠を集める側（`collectEvidenceStmts` / `fnDeclEvidence` / `programEvidence`）は、**式が出てくる場所すべて**で `callEvidence` を呼ぶ。

- `let`（注釈あり・なし）の右辺、代入の右辺、`return` の式
- `if` / `while` の条件式
- 関数本体の末尾式、暗黙 main の末尾式

`SReturn` と末尾式では、これに加えて `resolveExprType` で戻り値（`ReturnSlot`）の証拠も作る。

- **`callEvidence`**：式の中の呼び出し → `ParamSlot`
- **`resolveExprType`**：式そのものの型 → `ReturnSlot`

という分担。

### 注意点

**1. コメントと実装が合っていない。**
コメントには「宣言済みの仮引数の個数を超える位置はスキップする」とあるが、実装は `zip [0 ..] args` で**すべての実引数**に証拠を作っている。

- 実害はない。`resolveOne` は未解決スロット（`pending`）についてしか証拠を引かないので、`ParamSlot f 5` のような存在しないスロットの証拠は読まれず捨てられる
- 同じ理由で、型注釈済みの仮引数への証拠や、未宣言関数への呼び出しの証拠も作られるが、無視されるだけ（未宣言関数そのものは `resolveExprType` の `Call` でエラーになる）
- ただし、余分な実引数の中にある確定エラー（例：`1i32 + 2i64`）は、ここで評価されて推論の段階でエラーになる。どのみち後段でエラーになるので、結果は変わらない

コメントを「存在しないスロットへの証拠は `resolveOne` で参照されないため無視される」に直すと実装と合う。

**2. 確定エラーは推論全体を止める。**
`resolveExprType` が `Left err` を返すと、`do` 記法の中でそのまま伝わり、`resolveSlots` 全体がエラーで終わる。待ち（`Right (Left slot)`）とは扱いがはっきり分かれている。

**3. 同じスロットへの証拠は複数たまる。**
同じ関数を何か所から呼んでも、各呼び出しの証拠がすべてリストに入る。`resolveOne` はそれらを `unifyMaybeType` でまとめるので、`f(1i32)` と `f(2i64)` が両方あると、そのスロットの推論で型不一致エラーになる。

## 4. `resolveOne`

`src/Compiler.hs:729`

```haskell
resolveOne :: (Eq a) => [(a, Either a (Maybe Type))] -> a -> Either String (Either a Type)
resolveOne evidence slot = do
  let candidates = [c | (s, c) <- evidence, s == slot, c /= Left slot]
  case [s' | Left s' <- candidates] of
    (blocker : _) -> Right (Left blocker)
    [] -> do
      u <- foldM unifyMaybeType Nothing [mty | Right mty <- candidates]
      Right (Right (maybe (TyInt W64) id u))
```

固定点ループ（`resolveSlots`）の1ラウンドで、**未解決のスロット1つについて、集まった証拠からこのラウンドで型を決められるかを判定する**関数。

型は `Slot` ではなく多相の `a` になっている。実際には `a = Slot` で使われる。`Eq` しか要求しないので、単体テストで文字列などを使うこともできる。

### 戻り値の3通り

| 値 | 意味 | `resolveSlots` での扱い |
|---|---|---|
| `Left err` | 証拠同士が矛盾している（例：`i32` と `i64`） | 推論全体がエラーで終わる |
| `Right (Left blocker)` | 別のスロット `blocker` の解決待ち | `stillPending` に残り、次のラウンドで再判定 |
| `Right (Right ty)` | 型が決まった | `advanced` に入り、`resolved` に追加される |

1ラウンドで `advanced` が空（1つも前進しない）なら、`resolveSlots` は `circular type inference: A -> B` エラーを出す。

### 処理の3段階

#### (1) 候補を絞る

```haskell
candidates = [c | (s, c) <- evidence, s == slot, c /= Left slot]
```

`programEvidence` が集めたプログラム全体の証拠のうち、**このスロットに関するもの**だけを取り出す。その際、**自分自身を待っている証拠（`Left slot`）は除外**する。

除外しないと、自己再帰の関数が推論できない。

```
fn fact(n: i64) { if n <= 1 { return 1; } n * fact(n - 1) }
```

`ReturnSlot fact` の証拠は次の2つ。

- `return 1` → `Right Nothing`
- 末尾式 `n * fact(n - 1)` → `Left (ReturnSlot fact)`（自分待ち）

自分待ちを残すと、永久に待ち状態のままになる。除外すれば `return 1` だけが残り、`i64` に決まる。

#### (2) 他のスロット待ちが1つでもあれば保留する

```haskell
(blocker : _) -> Right (Left blocker)
```

自分以外のスロットを待っている証拠が1つでもあれば、**確定済みの証拠がほかにあっても**このラウンドでは決めない。一部の証拠だけで型を決めてしまうと、あとで判明する証拠と矛盾したときに取り消せないため。返すのは先頭の待ち相手1つだけで、これは循環エラーのメッセージ（`A -> B`）に使われる。

#### (3) すべて確定していれば単一化する

```haskell
u <- foldM unifyMaybeType Nothing [mty | Right mty <- candidates]
Right (Right (maybe (TyInt W64) id u))
```

- `Nothing`（型が未確定のリテラル）から始めて、`unifyMaybeType` で証拠を順にまとめる
  - `Nothing` と `Just t` → `Just t`（リテラルは相手の型に合わせる）
  - `Just i32` と `Just i64` → エラー
- 最後まで `Nothing` のまま（リテラルしかない）なら **`i64` にデフォルト**する
- **証拠がまったくない**場合（呼ばれない関数の仮引数など）も、`foldM` の初期値 `Nothing` がそのまま残るので `i64` になる

`let` の型推論（`inferType`）と同じ規則。

### 例：普通の依存関係

```
fn g(x) { x }
g(3i32)
```

| ラウンド | `ParamSlot g 0` の候補 | 結果 | `ReturnSlot g` の候補 | 結果 |
|---|---|---|---|---|
| 1 | `[Right (Just i32)]` | `i32` に決定 | `[Left (ParamSlot g 0)]` | 保留 |
| 2 | ― | ― | `[Right (Just i32)]` | `i32` に決定 |

### 設計上の限界（実際にコンパイルして確認済み）

自分待ちの証拠は単純に除外されるだけなので、次の2つのケースでうまく動かない。

#### (A) 自己再帰で `i32` が使えない

```
fn fact(n) { if n <= 1 { return 1; } n * fact(n - 1) }
fact(5i32)
```

→ `Error: type mismatch: expected i64, found i32`

`n` が `i32` に決まっても、末尾式 `n * fact(n - 1)` は `combine` の中で `fact(...)` が自分待ちになり、**式全体が `Left (ReturnSlot fact)` になる**（`chainSlot` がそこで打ち切るため）。左辺 `n` の `i32` という情報も一緒に失われる。

その結果、残る証拠は `return 1` の `Nothing` だけになり、戻り値は `i64` にデフォルトされる。そのあとのコード生成で、`i64` を期待する位置に `i32` の `n` が来るので型エラーになる。仮引数に `n: i32` と注釈を書いても同じエラーになる。回避するには戻り値型を明示するしかない。

#### (B) 戻り値型を省略した相互再帰は循環エラーになる

```
fn is_even(n: i64) { if n == 0 { return true; } is_odd(n - 1) }
fn is_odd(n: i64)  { if n == 0 { return false; } is_even(n - 1) }
is_even(4)
```

→ `Error: circular type inference: is_even return type -> is_odd return type (add an explicit type annotation to break the cycle)`

`ReturnSlot is_even` の候補には `Right (Just bool)`（`return true`）があるが、`Left (ReturnSlot is_odd)` も含まれているので、段階(2)で保留になる。`is_odd` も同様に保留になり、どちらも決まらない。除外されるのは完全な自己ループだけなので、長さ2以上の循環は、`return` から型が分かっていても解決できない。

CLAUDE.md には「`is_even`/`is_odd`のような相互再帰を循環と誤検出しないための要」とあるが、テスト（`test/Spec.hs:751`, `:1101`）は戻り値型を注釈した形しか試していない。**実際に守られているのは「仮引数型が省略された相互再帰」だけ**（仮引数スロットは呼び出し側の実引数から決まり、自分の戻り値を待たないため）。

#### 改善の方向性

どちらの問題も、「待ちになった証拠を丸ごと捨てるのではなく、分かった部分の型情報を残す」ようにすると改善できる。たとえば `combine` の片側が待ちでも、もう片側の確定型を証拠として残す方法が考えられる。

[SlotResultの使われ方について]
  型 :Either String (Either Slot (Maybe Type))

ロジックだけを見ると、スロットだけでなく変数も混ざりそうに見えるが、名前からはスロット限定の型のはず。
そこで、「変数が混ざるケースは実際には呼び出されないのではないか？」という仮説を立て、
resolveExprTypeの呼び出し元を調査
１）addressOfSlot (Either String (Either Slot Type))
 resolveExprTypeの型：Either String (Either Slot (Maybe Type))
  自身の型                             ：Either String (Either Slot        Type)
 Just (TPtr inner) → Right inner 
 Just _            → Left (ポインタ化できない)
 Nothing           → Left (型が未定義)
  ①addressOfSlotの返り値は、変数の場合も、スロットの場合もあり得る。
  ②addressOfSlotはresolveExprTypeからしか呼び出されない
  ③resolveExprTypeのaddressOfSlot以外（２，３，４）からの呼び出しの場合、必ずスロット（仮引数 or 返り値）のため、必ずスロットになる。（OK）

２）callEvidence (Either String Evidence)
  Callの場合のみRight それ以外はLeftなので、スロットしか返さない。（OK）

３）collectEvidenceStmts (Either String (LocalEnv, Evidence))
  let a = xxx →変数 →LocalEnvのみ追加、Evidenceは追加しない（OK）
  return a →スロット（OK）
４）fnDeclEvidence
  return a →スロット（OK）
